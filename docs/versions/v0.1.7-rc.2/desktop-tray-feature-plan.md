# v0.1.7-rc.2 桌面端系统托盘功能规格与执行计划

> 状态：待实施，供其他 agent 按本文档执行
> 版本：v0.1.7-rc.2
> 范围：Tauri 主桌面壳 + Electron macOS 兼容桌面壳
> 本文档性质：实现规格，不包含本次功能的代码实现

## 1. 目标

为 DeepSeek Harness Desktop 增加系统托盘驻留能力：用户点击主窗口右上角关闭按钮时，应用不退出，而是隐藏到系统托盘；只有点击托盘菜单中的“退出”才真正退出应用。

用户可见行为必须是：

1. 点击主窗口右上角关闭按钮：主窗口隐藏，桌面应用进程继续运行，内嵌 dsh Node 子进程继续运行。
2. 双击托盘图标：主窗口恢复、显示并获得焦点。
3. 右键托盘图标：显示两个菜单项，且顺序固定为：
   1. `打开主界面`
   2. `退出`
4. 点击 `打开主界面`：主窗口恢复、显示并获得焦点。
5. 点击 `退出`：真正退出桌面应用，并可靠回收内嵌 dsh Node 子进程。

Tauri 和 Electron 两套桌面壳必须保持上述行为一致。Windows 主版本首先完成并验证，Electron 兼容版不能继续保留“关闭窗口即退出”的旧行为。

## 2. 当前实现背景

### 2.1 Tauri 主桌面壳

主要入口：

- `tauri-app/src-tauri/src/main.rs`
- `tauri-app/src-tauri/Cargo.toml`
- `tauri-app/src-tauri/tauri.conf.json`

当前行为：

- 在 `setup` 中启动内嵌 Node，运行 `dsh web --port 0 --no-open`。
- 解析 ready URL 后动态创建名为 `main` 的 WebviewWindow。
- 使用 `tauri-plugin-single-instance` 处理第二实例，恢复并聚焦已有窗口。
- 使用 `RunEvent::Exit` 回收 dsh child。
- 当前没有应用级托盘交互，也没有拦截主窗口的用户关闭事件。

当前 Tauri 配置已经提供应用图标，Tauri 依赖树中也已有 `tray-icon` 底层能力。实现时优先使用 Tauri 2 的核心托盘/菜单 API，不额外引入重复的第三方托盘实现。

### 2.2 Electron macOS 兼容壳

主要入口：

- `electron-app/src/main.js`
- `electron-app/electron-builder.yml`
- `electron-app/icons/icon.png`

当前行为：

- 使用 Electron `BrowserWindow` 加载 dsh ready URL。
- 使用 `app.requestSingleInstanceLock()` 和 `second-instance` 恢复已有窗口。
- 当前 `window-all-closed` 会设置退出状态、回收 child 并调用 `app.quit()`。
- 当前没有 `Tray` 实例，也没有主窗口 `close` 事件拦截。

本功能需要将用户主动关闭窗口与应用真正退出区分开来，同时保留现有启动、下载、代理、日志、单实例和 child 异常退出逻辑。

## 3. 范围与非目标

### 3.1 本次范围

- Tauri 主壳的系统托盘、托盘菜单、托盘双击、主窗口关闭拦截。
- Electron 兼容壳的系统托盘、托盘菜单、托盘双击、主窗口关闭拦截。
- 显式退出状态和 child 回收路径的调整。
- 单实例恢复逻辑与托盘恢复逻辑统一。
- Windows 安装包和 macOS Electron 包的行为验收。

### 3.2 非目标

本次不实现以下内容：

- 开机自动启动。
- 登录后自动运行。
- 托盘常驻开关或设置项。
- 托盘通知、气泡通知、任务进度或菜单动态状态。
- 修改 dsh 官方运行时、dsh Web UI 或会话数据目录。
- 修改 `dsh web` 启动参数、ready URL 协议、token/cookie 处理、下载接管或代理设置。
- 自动更新、签名、公证或安装器交互改造。
- 新增“关于”“检查更新”“最小化”等托盘菜单项。

## 4. 交互规格

### 4.1 托盘图标

- 应用启动完成后必须存在一个托盘图标。
- 一个应用实例只能创建一个托盘图标。
- 托盘图标使用现有应用品牌图标，不新增独立品牌资源。
- Tauri 复用 Tauri 配置中的默认应用图标。
- Electron 复用 `electron-app/icons/icon.png`；如目标平台需要模板图标或特定尺寸，由实现 agent 按平台 API 处理，但不得改变用户看到的品牌。
- 托盘图标应设置可识别的 tooltip，建议使用 `DeepSeek Harness Desktop`。
- 应用退出后托盘图标必须消失，不能留下失效图标。

### 4.2 右键菜单

右键托盘图标必须显示且仅显示以下两个菜单项：

| 顺序 | 菜单文本 | 行为 |
|---|---|---|
| 1 | `打开主界面` | 恢复、显示并聚焦主窗口 |
| 2 | `退出` | 设置显式退出状态，真正退出应用并回收 dsh child |

要求：

- 菜单文本和顺序必须精确匹配。
- 不添加分隔线或其他菜单项，避免验收时出现额外项目。
- 菜单项动作必须复用统一函数，不能分别复制一套窗口恢复或退出逻辑。
- 点击 `打开主界面` 后菜单关闭，主窗口获得焦点。
- 点击 `退出` 后不得再次把窗口隐藏到托盘。

### 4.3 托盘双击

- 双击托盘图标必须执行与 `打开主界面` 相同的窗口恢复逻辑。
- 如果窗口处于最小化状态，先恢复再显示和聚焦。
- 如果窗口已经隐藏，直接显示并聚焦。
- 如果窗口已经显示，只需确保其获得焦点，不得创建第二个窗口。
- 双击操作不得启动第二个 dsh child，不得创建第二个托盘图标。
- 如果主窗口尚未创建，例如 dsh 仍在启动或启动失败，操作不得 panic、死锁或创建临时窗口；待正常创建后仍应能通过托盘打开。

### 4.4 主窗口关闭按钮

用户点击主窗口右上角关闭按钮时：

1. 拦截默认关闭行为。
2. 隐藏主窗口；必要时同时恢复其非最小化状态，避免下次打开保留异常最小化状态。
3. 保持桌面应用进程运行。
4. 保持 dsh Node 子进程运行。
5. 保持托盘图标运行。
6. 保留 WebView、会话状态、WebSocket 和当前页面状态。

关闭按钮不是“退出”操作。实现不得在该路径调用 `app.quit`、`app.exit`、`kill_child` 或等价的进程回收逻辑。

### 4.5 显式退出

只有托盘菜单的 `退出` 才执行真正退出流程：

1. 设置线程安全的 `quitting`/`exit_requested` 状态。
2. 进入现有应用退出入口。
3. 允许主窗口关闭或销毁，不再被 close 拦截逻辑改成隐藏。
4. 回收 dsh child；必要时等待 child 结束。
5. 清理托盘对象或让平台 API 随应用退出清理。
6. 桌面应用进程退出。

退出流程必须幂等。重复点击、退出过程中再次触发菜单或窗口事件，都不能 panic、死锁或留下 child 进程。

## 5. 生命周期状态模型

实现应按照以下语义处理状态，不要求函数名完全一致，但必须能表达同样的边界：

```text
STARTING
  -> READY_VISIBLE       dsh 就绪、主窗口显示、托盘存在
  -> STARTUP_FAILED      启动失败，按现有错误路径退出

READY_VISIBLE
  -- 用户关闭窗口 --> HIDDEN_IN_TRAY
  -- 托盘双击/打开 --> READY_VISIBLE（恢复并聚焦）
  -- 托盘退出 --> EXITING
  -- dsh child 退出 --> CHILD_STOPPED

HIDDEN_IN_TRAY
  -- 托盘双击/打开 --> READY_VISIBLE（显示并聚焦）
  -- 用户重复关闭 --> HIDDEN_IN_TRAY（幂等）
  -- 托盘退出 --> EXITING
  -- dsh child 退出 --> CHILD_STOPPED

EXITING
  -> STOPPED             回收 child、清理托盘、进程结束

CHILD_STOPPED
  -> STOPPED             不留下仅有托盘的死 UI，不保留孤儿 desktop/Node 进程
```

关键原则：

- 用户关闭窗口与程序主动退出必须可区分。
- dsh child 异常退出必须绕过“用户关闭即隐藏”的逻辑。
- 应用隐藏不等于 child 停止。
- 托盘恢复不等于重新启动 dsh。

## 6. Tauri 实施规格

### 6.1 托盘创建

在 Tauri 应用初始化期间创建一个唯一托盘实例：

- 使用 Tauri 2 核心 `TrayIconBuilder`/对应菜单 API，具体 API 以当前锁定的 Tauri 2 版本编译结果为准。
- 从应用默认图标取得托盘图标；不要复制一套新的图标文件。
- 使用固定 ID，例如 `main-tray`，防止初始化流程重复创建。
- 创建两个菜单项，文本分别为 `打开主界面`、`退出`。
- 绑定托盘菜单事件和双击事件。
- 记录托盘初始化失败日志。

托盘应在应用生命周期足够早的阶段初始化，使窗口隐藏后托盘仍然可用；但如果当前实现必须等资源或窗口创建完成后才能初始化，应确保初始化只执行一次，并覆盖 dsh 启动失败和窗口尚未创建的边界。

### 6.2 窗口恢复函数

抽取统一的主窗口恢复函数，供以下路径共同调用：

- `tauri-plugin-single-instance` 的第二实例回调。
- 托盘双击。
- 托盘菜单 `打开主界面`。

恢复函数至少应：

1. 获取 `main` WebviewWindow。
2. 如处于最小化状态，调用 `unminimize`。
3. 调用 `show`。
4. 调用 `set_focus`。
5. 窗口不存在时静默记录或返回，不创建第二个窗口。

不要在三个回调中复制三套略有差异的恢复实现。

### 6.3 用户关闭拦截

给 `main` WebviewWindow 注册窗口事件处理：

- 在 `CloseRequested` 中区分用户关闭和应用主动退出。
- 用户关闭且未进入退出状态时调用 `prevent_default`，然后隐藏主窗口。
- 应用已经设置退出状态时不得调用 `prevent_default`，让正常退出流程继续。
- dsh child 异常退出时如果需要关闭窗口，必须先设置内部状态或采用不会再次触发隐藏的关闭方式，确保应用最终退出而不是仅剩托盘。

实现状态必须是线程安全的，因为 Tauri 窗口事件、托盘回调、child 监听和 `RunEvent` 可能在不同执行上下文中发生。不得使用只存在于 `setup` 局部作用域且无法被其他回调访问的普通布尔变量。

### 6.4 退出和 child 回收

保留现有 `RunEvent::Exit` 中的 child 回收机制。托盘 `退出` 必须走该机制，不得只隐藏窗口或只删除托盘。

同时检查以下路径是否与新 close 拦截兼容：

- dsh 启动失败。
- dsh child 正常退出。
- dsh child 异常退出。
- 应用收到系统退出事件。
- 第二实例启动。
- 托盘退出。

若需要新增退出辅助函数，必须保证它与现有 `AppState.child` 的 `Arc<Mutex<Option<Child>>>` 所有权和锁定方式一致，不产生双重 kill、锁死或 child 句柄泄漏。

### 6.5 依赖和权限边界

- 优先使用当前 Tauri 2 已经提供的核心托盘和菜单能力。
- 只有编译实际要求时才修改 `Cargo.toml` 或 `Cargo.lock`；不能为了托盘随意升级 Tauri、Rust crate 或其他依赖。
- 托盘由 Rust 主进程创建时，不应为了本功能扩大 WebView 前端权限。
- 检查 `tauri-app/src-tauri/gen/schemas/acl-manifests.json` 和相关 capabilities 是否需要同步；如不需要修改，应在实施记录中明确说明。
- 不修改 `tauri.conf.json` 的窗口尺寸、资源路径、图标集合和运行时资源配置，除非编译验证证明托盘图标无法从现有配置取得。

## 7. Electron 实施规格

### 7.1 Tray 创建

在 `electron-app/src/main.js` 中增加长期持有的 `Tray` 实例：

- 从 Electron `Tray` 创建唯一托盘对象。
- 使用 `electron-app/icons/icon.png` 作为现有品牌图标。
- 使用 `Menu.buildFromTemplate` 创建且仅包含两个菜单项：`打开主界面`、`退出`。
- 给托盘设置 tooltip `DeepSeek Harness Desktop`。
- 托盘对象必须由主进程变量持有，不能只保存在局部变量中，否则可能被回收或无法响应事件。
- 初始化流程必须幂等，第二实例回调不得创建新 Tray。

### 7.2 窗口恢复

新增统一的恢复/聚焦函数，供以下路径调用：

- `second-instance`。
- Tray `double-click`。
- 菜单 `打开主界面`。

函数至少处理：

- BrowserWindow 已销毁时安全返回。
- `isMinimized()` 时先 `restore()`。
- `show()`。
- `focus()`。

不得在托盘动作中重新执行 `startDsh()` 或创建新的 BrowserWindow。

### 7.3 close、before-quit 和 window-all-closed

调整当前生命周期逻辑：

- BrowserWindow 的 `close` 事件：未进入显式退出状态时 `preventDefault()` 并 `hide()`。
- 显式退出状态为真时允许窗口真正关闭。
- `before-quit` 继续设置退出状态并回收 child，避免程序主动关闭窗口时被 close 事件再次隐藏。
- 用户点击关闭后不应触发 `window-all-closed` 导致应用退出，因为 close 已被拦截。
- 不要依赖旧的 `window-all-closed -> app.quit()` 作为用户关闭行为；需要重新确认它与新的隐藏语义、macOS 生命周期和显式退出流程是否兼容。
- 外部信号仍然必须设置退出状态并回收 child。

### 7.4 child 异常退出

现有 `onChildExit` 的语义必须保留并与托盘兼容：

- dsh child 非主动退出时，不能留下可以点击但没有后端的托盘驻留应用。
- 必须关闭窗口并结束桌面应用，或进入明确的错误退出流程。
- 程序主动退出导致的 child 退出不得再次触发错误关闭逻辑。
- 最终不得留下 Electron 主进程或 dsh Node 子进程。

### 7.5 Electron 打包边界

- 复用现有 `electron-builder.yml` 的图标与打包配置。
- 不新增自动更新、签名、公证或安装器逻辑。
- 不改变 runtime 的 `extraResources` 路径。
- 如果 macOS 对托盘图标有模板图标要求，优先在已有图标资源基础上处理，并记录平台差异；不能把本次功能扩展成完整品牌资源重构。

## 8. 异常和兼容处理

### 8.1 托盘初始化失败

托盘是本功能的必要能力，不能静默创建一个“关闭后不可恢复”的隐藏窗口。实现应遵循以下规则：

- Windows 和 macOS 目标构建中，托盘初始化失败必须写入可诊断日志，并阻止启用“关闭即隐藏”路径，或直接按启动失败处理；不能让窗口隐藏后没有恢复入口。
- 若某个桌面平台确实不支持托盘，必须明确采用可用的降级行为：保留原有关闭即退出语义，并让用户仍能通过窗口正常退出；不得假装已经支持托盘。
- 具体降级方式需在实施结果中记录平台和原因，不能无日志静默降级。

### 8.2 窗口尚未创建

dsh 启动期间可能已经创建托盘但尚未创建主窗口。此时：

- `打开主界面` 和双击动作不得创建第二个 dsh 或第二个窗口。
- 可以安全忽略本次打开请求，并记录调试日志。
- dsh 成功后只创建一个主窗口，托盘仍使用原实例。

### 8.3 dsh child 异常退出

child 不存在时，WebView 已经不能继续工作。不得只隐藏窗口并保留托盘。必须触发明确的关闭/退出流程，确保：

- 不残留无效主窗口。
- 不残留仅能显示菜单但不能打开界面的托盘应用。
- 不残留 Node/dsh 子进程。

### 8.4 单实例

保持现有单实例约束：

- 第二次启动不得创建第二个桌面进程、第二个 dsh child、第二个主窗口或第二个托盘图标。
- 第二实例回调必须复用统一恢复函数。
- 当原实例处于托盘隐藏状态时，第二次启动应将原主窗口恢复并聚焦。

## 9. 预期变更文件

实现 agent 应尽量将变更限制在以下文件：

- `tauri-app/src-tauri/src/main.rs`
  - Tauri 托盘创建和菜单。
  - 主窗口 close 拦截。
  - 显式退出状态。
  - 统一窗口恢复逻辑。
  - 与 child 异常退出的协调。
- `electron-app/src/main.js`
  - Electron Tray、菜单和双击事件。
  - BrowserWindow close 拦截。
  - 显式退出状态与 child 生命周期协调。
  - 统一窗口恢复逻辑。
- `tauri-app/src-tauri/Cargo.toml`、`Cargo.lock`
  - 仅当当前 Tauri 核心 API 编译确实要求依赖或 feature 变化时修改。
- Tauri capability/权限文件
  - 仅当实际编译或运行需要时修改，并在实施记录中解释原因。
- 与本功能直接相关的测试或验证脚本、验收记录。

明确禁止修改：

- `tauri-app/resources/runtime/` 中的官方 dsh 运行时。
- dsh Web UI 和官方源代码。
- `~/.dsh` 用户数据。
- 无关版本号、发布脚本、NSIS 安装逻辑和历史安装包。
- 与托盘无关的下载、代理、会话 cookie、URL 解析和日志脱敏逻辑。

## 10. 测试与验收矩阵

### 10.1 基础启动

- 启动 Tauri Windows 版本后，存在一个桌面进程、一个 dsh child、一个主窗口和一个托盘图标。
- 启动 Electron macOS 兼容版本后，存在一个 Electron 主进程、一个 dsh child、一个主窗口和一个托盘图标。
- 主窗口可以正常加载官方 UI，现有 WebSocket、会话和下载行为不回归。

### 10.2 关闭到托盘

- 点击右上角关闭按钮。
- 主窗口从任务栏/桌面隐藏。
- 桌面应用进程仍存在。
- dsh child 仍存在且服务仍可用。
- 托盘图标仍存在。
- 没有弹出第二个窗口，没有创建第二个 child。

### 10.3 托盘恢复

分别验证：

- 双击托盘图标。
- 右键托盘图标，点击 `打开主界面`。
- 窗口原本已最小化。
- 窗口原本已隐藏。
- 窗口原本已经显示。
- 连续双击或连续点击打开。

预期均为恢复/显示/聚焦原主窗口，不新建实例、不重启 dsh。

### 10.4 菜单精确性

右键托盘图标并检查：

- 只有两个菜单项。
- 第一项精确为 `打开主界面`。
- 第二项精确为 `退出`。
- 没有额外菜单项或意外分隔线。
- 双击图标不会显示错误菜单或创建重复菜单。

### 10.5 真正退出

- 关闭主窗口到托盘后，右键点击 `退出`。
- 桌面进程退出。
- dsh Node child 退出。
- 托盘图标消失。
- 没有残留 node/dsh 进程。
- 重复点击退出或退出过程中触发窗口事件不会死锁或崩溃。

### 10.6 异常退出

- 手动结束 dsh child。
- 验证主窗口不会留下可见但无后端的空壳。
- 验证应用不会只剩一个无效托盘图标。
- 验证最终 desktop 和 dsh 进程均退出或进入已有明确错误退出流程。

### 10.7 单实例回归

- 应用已经显示时再次启动：原窗口聚焦，进程/child/托盘数量不增加。
- 应用已经隐藏到托盘时再次启动：原窗口恢复并聚焦，进程/child/托盘数量不增加。
- dsh 正在启动且主窗口尚未创建时再次启动：不创建第二个 child，不触发 panic。

### 10.8 静态和打包验证

实现完成后至少执行：

- Rust 格式和编译检查。
- Electron JavaScript 语法检查。
- Tauri Windows 生产构建并在安装包中验证托盘功能。
- Electron macOS 兼容包构建并在目标 macOS 环境验证托盘功能。
- 现有单实例、下载另存为、WebSocket、child 异常退出回归检查。

仅通过 `cargo check`、`node --check` 或查看代码不能作为本功能完成依据；托盘交互必须在真实运行的桌面包中验证。

## 11. 风险与实现注意事项

| 风险 | 影响 | 要求 |
|---|---|---|
| close 拦截没有区分用户关闭和程序退出 | 点击退出后窗口再次被隐藏，应用无法退出 | 使用线程安全退出状态，并在主动退出路径先设置状态 |
| child 异常退出仍走隐藏逻辑 | 留下无后端的托盘死 UI | 异常路径必须绕过用户关闭拦截并最终退出 |
| Tray 只保存在局部变量 | 托盘图标消失或回调失效 | 由主进程/应用状态长期持有 |
| 托盘初始化重复 | 出现多个图标或重复菜单回调 | 使用单例变量或固定 ID，初始化幂等 |
| 单实例回调复制恢复逻辑 | 关闭到托盘后第二次启动行为不一致 | 所有入口复用同一个恢复函数 |
| macOS/Linux 托盘事件差异 | 双击事件不可用或图标显示异常 | 目标平台实际验证，并保留右键“打开主界面”作为明确恢复入口 |
| 托盘初始化失败后仍隐藏窗口 | 用户无法恢复主界面 | 失败时不得启用不可恢复的隐藏语义，必须日志化降级或退出 |
| 为本功能升级大量依赖 | 引入无关兼容和打包风险 | 优先使用当前 Tauri/Electron 能力，最小变更 |

## 12. 完成定义

满足以下条件才可将本功能标记为完成：

1. Tauri 和 Electron 两套桌面壳均实现托盘驻留和窗口恢复。
2. 用户点击关闭按钮不会真正退出，dsh child 继续运行。
3. 双击托盘图标和菜单 `打开主界面` 都能恢复并聚焦原窗口。
4. 托盘右键菜单仅包含规定的两个菜单项，文本和顺序精确匹配。
5. 菜单 `退出` 能真正退出应用并回收 child，无残留进程和托盘图标。
6. dsh child 异常退出不会留下死窗口或死托盘。
7. 单实例行为没有回归，不会增加窗口、child 或托盘实例。
8. Windows Tauri 安装包和 macOS Electron 兼容包均完成真实运行验收。
9. 实际代码改动没有触及官方 dsh 运行时、Web UI、用户数据和无关构建逻辑。
10. 验收记录包含本文档第 10 节中的通过/失败结果和测试环境信息。

## 13. 建议实施顺序

1. 先在 Tauri 主壳实现统一窗口恢复函数和线程安全退出状态。
2. 接入 Tauri 托盘图标、两个菜单项、双击事件和 close 拦截。
3. 在 Windows 开发运行和生产安装包中完成第 10 节的 Tauri 验收。
4. 再在 Electron 兼容壳实现同等状态机、Tray 和 close 拦截。
5. 在 macOS 兼容环境完成 Electron 验收，并对照 Tauri 行为检查一致性。
6. 最后执行单实例、child 异常退出、现有下载/会话功能回归，并提交变更摘要和验收记录。

实施 agent 不得在未通过基础关闭/退出验收前扩展到通知、自动启动或托盘设置等其他功能。
